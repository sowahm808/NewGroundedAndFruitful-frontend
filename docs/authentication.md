# Authentication

Adults authenticate with Firebase email/password and use Firebase password reset. A child submits family code, handle, and PIN over TLS to a protected, rate-limited backend exchange endpoint. The backend validates the mapping and returns a Firebase custom token; the client creates only a Firebase Auth session and clears the PIN.

Firebase Authentication proves identity. After restoration or sign-in, Angular calls the authenticated `GET /api/v1/auth/session` backend bootstrap (the API client base already includes `/api/v1`). Its `uid`, `displayName`, `roles`, `disabled`, and `membershipState` fields are the application-session source of truth. The boundary normalizes documented legacy role spellings, rejects unknown roles, and never supplies a default role. App Check must be initialized before production backend calls. Pending, disabled, role-required, session-error, and unauthorized states are distinct. Logout terminates Firebase Auth state and clears the in-memory application session. Application code never stores credentials, PINs, claims, roles, or tokens in local storage.
