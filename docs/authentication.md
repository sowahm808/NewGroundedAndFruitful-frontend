# Authentication

Adults authenticate with Firebase email/password and use Firebase password reset. A child submits family code, handle, and PIN over TLS to a protected, rate-limited backend exchange endpoint. The backend validates the mapping and returns a Firebase custom token; the client creates only a Firebase Auth session and clears the PIN.

Firebase Authentication proves identity. After restoration or sign-in, Angular calls the authenticated `GET /api/v1/auth/session` backend bootstrap (the API client base already includes `/api/v1`) and unwraps its `data` envelope. The enclosed `uid`, `displayName`, `roles`, `disabled`, `onboardingStatus`, and `memberships` fields are the application-session source of truth. If `claimSynchronization.tokenRefreshRequired` is set, Angular force-refreshes the Firebase ID token once and performs one follow-up session request; backend roles remain authoritative even if synchronization is still pending. App Check must be initialized before production backend calls. Pending, disabled, role-required, session-error, and unauthorized states are distinct. Logout terminates Firebase Auth state and clears the in-memory application session. Application code never stores credentials, PINs, claims, roles, or tokens in local storage.
